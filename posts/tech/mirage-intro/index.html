Mirage 技术分析#

论文#

现状#

  • 手动设计
    • 依赖专家大量工程努力，可能无法发现所有可能的优化，特别是多个计算层次需要协调的优化
  • 基于调度的优化
    • 代表：Halide、TVM（Tensor Virtual Machine）、Ansor 等
    • 基于算法和调度分离的思想，主要关注在计算不同层次的调度变换，通常不考虑算法级别变换，因此限制了优化的可能性
  • 基于代数变换的优化
    • 代表：TASO、Grappler、Tensat、PET 等。
    • 关注算法级别的代数变换，例如将卷积转换成matmul，但需要程序员手动去定义和实现可用的内核，实际性能受限于程序员的工程实践
  • 现有的super optimizer
    • 主要关注Kernel层的代数变换，不能发现在GPU多计算层次中联合代数变换和调度变换的复杂优化

主要内容#

提出$\mu Graph$ 多层次图表示，分成三个层次：

  • Kernel Graph
  • Thread Block Graph
  • Thread Graph

通过$\mu Graph$表示法统一捕捉代数和调度变换，在三个层次中进行联合优化，能够发现更深层次的优化机会。

对tensor program做如下步骤

  • 代数表达式分解
  • SMT求解(z3 solver)、图生成
  • 概率等价验证，获得一系列Valid Graph
  • Transpiler代码生成cuda代码（优化Layout等内容）
    • Mirage的include目录提供了生成的cuda代码依赖的runtime文件
  • 测试生成代码性能，选择最优的
    • nvcc将cuda代码编译成so文件
    • python module加载so
    • 运行测试时间后保留性能最强的

  • 输入PyTorch程序：Mirage的工作流程从输入一个PyTorch程序开始。

  • uGraph生成器搜索：

    • Mirage的uGraph生成器会自动搜索与输入功能匹配的可能uGraph。

    • 该搜索过程会捕获内核、线程块和线程级别的一系列GPU优化。

  • 等价验证：

    • 每个在此过程中生成的候选uGraph都会被转发到等价验证器。

    • 等价验证器检查uGraph是否与输入等价。

  • uGraph转译：

    • uGraph转译器将所有经过验证的uGraph转换为CUDA内核。

  • 通过profile识别性能最佳内核并返回

和传统的CUDA或者现在的Triton编程相比，是一种范式的改变，作者提出三大优势（这个技术路线可能做到的，不是现在已经做到）：

  • 更高的生产力
    • 在Pytorch级别指定想要的计算，后面Mirage接管，自动生成适合各种GPU架构的高性能内核
    • 将程序员从低级、特定体系架构的繁重任务中解放出来
  • 更高的性能：自动搜索可能的优化，生成内核
  • 正确性更强：形式化验证技术自动验证GPU内核的正确性

和Triton对比

  • Triton的算法是程序开发者决定，不会做代数层面的优化
  • Triton通过编译器优化，基于一些预定义规则和启发式方法
  • Triton调度层面autotune优化策略依赖于自定义，搜索空间有限

当前状态#

  • 实验性阶段
  • 只看到有推理场景的应用
  • 发布了0.2版本，开发不太活跃，还没有形成社区
  • 较多bug，没有稳定的API接口， 代码中很多案例跑不起来
  • 当前没有相关的生态和应用
  • 文档内容少，比较旧，对应的是早期的代码，目前文档中例子很多无法运行

未来发展方向#

  • 完善Python封装
  • 作为代码生成器，将$\mu Graph$ 转换成cuda或者triton代码
  • 支持NVIDIA更多架构的GPU
  • 支持AMD
  • 支持混合精度

Python接口#

当前发现问题#

  • superoptimzer优化后给出的Kernel可以运行，但是结果不正确， 并且同样的输入多次运行，会有不同的输出
  • 部分Graph，用superoptimzer无法生成Kernel
  • 代码中支持从$\mu Graph$生成Triton代码, 实际不可行
  • 代码中声称支持的jit功能，一跑就core dump报错（Transpiler代码问题）

作者案例#

RMS Norm + MatMul#

利用代数的交换律，将除法移动到MatMul之后，重新排列功能等效，但减少了device memory的访问

  • 效果

Attention with Query-Key Normalization#

例如QK-Norm这种Attention的变体，标准的Attention中不包含这个LayerNorm的计算过程，需要单独启动Kernel，这时就涉及device memory的访问。Mirage自动融合并生成自定义内核。

手写Graph (RMSNorm + MatMul)#

  • torch实现
rms_norm = torch.nn.RMSNorm(4096, device='cuda:0', dtype=torch.float16)
#@torch.compile
def torch_rms_norm(X, W):
    D = rms_norm(X)
    E = torch.matmul(D, W)
    return E
  • mirage实现
# generate code
graph = mi.new_kernel_graph()
X = graph.new_input(dims=(16, 4096), dtype=mi.float16)
W = graph.new_input(dims=(4096, 4096), dtype=mi.float16)
tb_graph = mi.new_threadblock_graph(grid_dim=(64,1,1), block_dim=(128,1,1), forloop_range=64, reduction_dimx=64)
tX = tb_graph.new_input(dtensor=X, input_map=(-1, -1, -1), forloop_dim=1)
tW = tb_graph.new_input(dtensor=W, input_map=(1, -1, -1), forloop_dim=0)
tM = tb_graph.matmul(tX, tW)
tAccX = tb_graph.forloop_accum(tX, "rms")
tAccM = tb_graph.forloop_accum(tM)
tO = tb_graph.div(tAccM, tAccX)
tb_graph.new_output(stensor=tO, output_map=(1, -1, -1))
O = graph.customized([X, W], tb_graph)
